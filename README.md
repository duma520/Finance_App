## 第一部分：写给所有人——3 分钟看懂这个软件

### 1.1 这是什么？

**人民币收支管理系统**（程序文件名 `Finance_App.py`）是一款运行在 Windows 电脑上的**个人/家庭记账软件**。它用 Python 3.10 编写，界面用 PyQt5，数据存在本地的 SQLite 数据库里，**不联网、不上传、不收集你的任何数据**。

一句话总结：**它帮你把"钱从哪来、花到哪去"记清楚，并且能自动帮你把银行发来的短信/微信提醒变成一条记账记录。**

### 1.2 它适合谁？

| 人群 | 能用来干什么 |
| --- | --- |
| 学生 | 记录生活费收支，看看钱花在哪 |
| 上班族 | 记工资、房租、餐饮、交通，做月度预算 |
| 家庭主妇/主夫 | 管理家庭多个账户（现金、银行卡、支付宝、微信） |
| 个体户/小微企业主 | 记录经营收支、借款还款、多账户余额 |
| 财务人员 | 导出 CSV/Excel 做进一步分析 |
| 程序员 | 阅读源码、二次开发、学习 PyQt5 + SQLite 项目结构 |

### 1.3 它有什么特色？

1. **完全本地**：数据在你自己的电脑上，加密可选。
2. **多用户**：一台电脑可以给全家人分别记账，互不干扰。
3. **交易提醒自动填写**（★ 最大亮点）：把银行公众号/支付宝/微信的交易提醒**粘贴进去**，自动识别金额、商户、日期、收支类型，一键填好。
4. **窗口大小、设置自动记住**：不用每次打开都重新调。
5. **数据变动后自动刷新**：选"最近一周"，加了新记录也能立刻看到。
6. **有冒烟测试**：四套测试脚本，共 231 项断言，保证改动不破坏老功能。

### 1.4 我需要什么才能运行它？

- 一台 Windows 电脑（Win7 及以上，推荐 Win10/Win11）
- 如果用打包好的 exe：**什么都不用装**，双击就能用
- 如果从源码运行：需要 Python 3.10 + PyQt5 等依赖（见第三部分）

### 2.1 每个版本的白话解释

**v4.0**：以前你设置了"自动备份保留 30 份"，关掉软件再打开，又变回默认了。这个版本开始，所有设置都存进数据库，重启后还在。窗口大小也开始被记住。

**v4.1**：以前收到银行短信，要手动抄金额、抄商户、抄时间。这个版本开始，你把短信内容**整段粘贴**到添加记录弹窗里，点一下"解析并填写"，金额、描述、日期自动填好，连"收入还是支出"都帮你选好。

**v4.2**：有些银行 App 的提醒是分行写的（"交易金额    人民币200.00"），标签和值之间是**空格**不是冒号。这个版本开始支持这种格式。而且如果提醒里没有"商户"，就用"交易附言"当描述。

**v4.3**：以前搜索框和 7 个筛选控件全挤在一行，分类名一长（比如"招商银行储蓄卡（尾号1234）"），窗口就被撑到 1400 多像素，缩都缩不下去。这个版本改成三行，窗口最小宽度从 1400 降到 735。

**v4.4**：以前窗口大小只在**正常关闭**时才保存，如果程序崩溃、被任务管理器强杀，尺寸就丢了。这个版本改成"你拖动完 800 毫秒后就自动保存"，不依赖正常退出。

**v4.5**：修 4.4 的一个 Bug——4.4 虽然实时保存了，但启动恢复时，程序内部有个"更新日期范围"的步骤会**顺手把默认窗口尺寸写回数据库**，导致你上次存的尺寸被覆盖。这个版本先读尺寸、再干别的，并且恢复期间禁止写尺寸。

**v4.6**：你选了"最近一周"，起止日期是**选的那一刻**算出来的（今天-7 到 今天）。如果程序开着过了一夜，第二天新增记录（日期是"今天"），就超出了旧的"到"，刚加完看不到。这个版本改成每次刷新都按当前时间范围重算。

**v4.7**：你粘贴"交易附言 银联无卡转账,对手户名-李红玲"，结果只填进去"银联无卡转账"，后面被吃了。原因是附言用了**商户的清洗器**，那个清洗器会在逗号处截断。这个版本给附言单独写了一个清洗器，**不按逗号切**，长度上限从 30 字放宽到 100 字。

**v4.8**：筛选栏字段宽度不统一（日期框 212、下拉框 118），标签也不对齐，看着凌乱。这个版本把筛选控件装进一个圆角面板，两行用**同一个网格**排，标签右对齐，7 个字段统一 118 像素宽。还加了"重置"按钮。

**v4.9**：新增"工具 → 设置…"对话框。第一个选项是"添加记录后自动滚动到列表底部"——开了之后，每次加完记录，列表自动滚到最底，方便看到刚加的那条。**设置项点选即保存**，没有"保存"按钮。

## 第三部分：从零开始——安装与第一次使用

### 3.1 方式一：用打包好的 exe（推荐小白）

如果你拿到的是 `Finance_App.exe`（在 `build_output\Finance_App.dist\` 目录里）：

1. 把整个 `Finance_App.dist` 文件夹复制到你想放的地方（比如 `D:\记账`）。
2. 双击 `Finance_App.exe`。
3. 第一次打开会弹出"用户登录"对话框。

**注意**：不要把 exe 单独拎出来，它需要同目录下的 `icon.ico` 等文件。

### 3.2 方式二：从源码运行（推荐开发者）

**第一步：装 Python**

去 https://www.python.org/downloads/ 下载 **Python 3.10**（推荐 3.10.11），安装时勾选"Add Python to PATH"。

**第二步：装依赖**

打开命令提示符（Win+R 输入 `cmd`），输入：

```
pip install PyQt5==5.15.9 PyQtChart pypinyin Pillow cryptography python-dateutil openpyxl
```

**第三步：运行**

进入项目目录，双击 `1.bat`（内容就是 `python Finance_App.py`），或者命令行：

```
cd /d 项目目录
python Finance_App.py
```

### 3.3 第一次打开会看到什么？

**① 用户登录对话框**

- **选择用户**：下拉框列出已有用户。第一次只有一个"默认用户"。
- **或创建新用户**：在这里输入名字，比如"爸爸"、"妈妈"、"小店"。
- **密码**：可以留空。如果填了密码并勾选"记住密码"，数据库会被**加密**。
- **记住密码**：勾选后密码存进主库，下次不用输。
- **管理用户**：重命名、删除用户。

**举例**：老王想给全家记账，他创建了三个用户："老王"、"老婆"、"孩子"。每个人的数据存在独立的 `finance_老王.db`、`finance_老婆.db`、`finance_孩子.db` 里，互不可见。

**② 主界面**

登录后看到主窗口，从上到下依次是：

1. **菜单栏**：文件、编辑、工具、帮助
2. **搜索/筛选面板**：圆角灰色面板，第一行搜索框+重置按钮，下面两行 8 个筛选控件
3. **标签页**：交易记录 / 统计分析 / 账户结余
4. **底部按钮**：添加记录、编辑记录、删除记录、标记为已结算、查看收据、刷新
5. **状态栏**：显示提示消息

## 第五部分：核心功能逐项详解（带大量举例）

### 5.1 记账：收入 / 支出

**场景**：小李今天发工资 8000 元。

1. 点"添加记录"。
2. 类型选"收入"。
3. 金额填 `8000`。
4. 类别选"工资"。
5. 日期默认今天。
6. 描述填"9月工资"。
7. 账户选"招商银行卡"。
8. 点确定。

**结果**：交易记录里多一条，类型显示"收入"（绿底），金额 8000.00。账户"招商银行卡"余额 +8000。

**场景**：小李中午吃饭花了 35 元。

1. 点"添加记录"。
2. 类型"支出"，金额 `35`，类别"餐饮"，描述"公司楼下快餐"。
3. 账户"支付宝"。
4. 确定。

### 5.2 借款与还款

**场景**：小王借给朋友 5000 元，朋友分两次还：先还 2000，再还 3000。

**第一步：记借款**

1. 添加记录 → 类型"借款" → 金额 `5000` → 描述"借给张三" → 账户"招商银行卡"。
2. 保存后，这条记录状态是"待还款"，表格里显示"借款 (剩余:5000.00)"。

**第二步：第一次还款**

1. 添加记录 → 类型"还款" → 金额 `2000`。
2. **关联借款**下拉框会列出所有待还款借款，选"ID:1 金额:5000 ..."。
3. 保存。

**结果**：借款状态仍是"待还款"，剩余变成 3000.00。

**第三步：第二次还款**

1. 添加记录 → 类型"还款" → 金额 `3000` → 关联同一笔借款。
2. 保存。

**结果**：系统发现还款总额 2000+3000=5000，等于借款金额，自动把借款状态改成"已结清"（绿底），剩余显示消失。

**超额还款场景**：朋友还了 6000（多还 1000）。

- 系统弹窗问："还款金额超过剩余应还金额 5000.00 元，是否将超额部分(1000.00元)记录为收入?"
- 选"是"：5000 记为还款，1000 记为收入（类别"退款"，描述"借款ID:1还款超额退款"）。
- 选"否"：取消，不记录。

### 5.3 余额 / 账户结余 / 待还款合计

这三个是**自动计算**的特殊类型：

| 类型 | 算什么 | 例子 |
| --- | --- | --- |
| 余额 | 所有账户的总余额（截至某日期） | 截至 2026-09-19 总余额 |
| 账户结余 | 某个账户的余额 | 招商银行卡截至今天的余额 |
| 待还款合计 | 所有待还款借款的剩余总额 | 现在总共还欠别人多少 |

**注意**：选这三种类型时，金额输入框会被**禁用**，因为系统自动算。

### 5.4 多账户管理

**场景**：老张有现金、招行卡、支付宝、微信四个账户。

1. 编辑 → 管理账户 → 添加。
2. 分别添加：
   - 现金账户，初始 500，CNY
   - 招商银行卡，初始 20000，CNY

之后记账时，账户下拉框能选这四个。账户结余页能看到每个账户的余额。

**多币种**：账户可以设 USD、EUR、JPY 等，配合"工具 → 汇率转换"使用。

- 支出：餐饮、购物、娱乐、交通、住房、医疗、教育、其他

### 5.10 搜索与筛选

**拼音搜索原理**：程序用 `pypinyin` 库把中文转成拼音首字母。比如"餐饮"→`cy`。你输入 `cy`，程序会：
1. 先直接 LIKE 匹配描述、金额、分类、标签、账户名。
2. 再把数据库里所有描述和分类转成拼音首字母，看哪些以 `cy` 开头。
3. 合并结果。

**组合筛选举例**：
- 类型"支出" + 分类"餐饮" + 时间范围"最近一月" → 看最近一月的餐饮支出。
- 状态"待还款" + 账户"招商银行卡" → 看招行卡上还没还的借款。

### 5.11 统计分析

**收支趋势**：柱状图，X 轴是分类，Y 轴是金额，两组柱子（收入、支出）。

**分类占比**：饼图，只显示支出分类。

**借款还款**：柱状图，X 轴是借款 ID，两组柱子（借款金额、已还款）。

**预算执行**：柱状图，X 轴是分类，两组柱子（预算、实际支出）。

**统计文本**（下方 HTML 表格）：
- 收支总览：总收入、总支出、总借款、总还款、净收入。
- 借款状态：总借款、已还款、待还款。
- 分类统计：每个类别的收入、支出、合计。

### 5.12 撤销操作

**原理**：每次数据变动前，程序把当前数据库复制一份成 `temp_undo_YYYYMMDD_HHMMSS.db`，压入 `operation_stack`（最多 10 个）。

按 Ctrl+Z 或 编辑 → 撤销：
1. 弹出栈顶备份文件。
2. 关闭当前数据库。
3. 用备份文件覆盖。
4. 重新加载。
5. 删除临时文件。

**注意**：撤销栈是内存里的，程序关闭就清空。临时文件每 6 小时清理一次（超过 24 小时的删掉）。

### 5.13 数据导入导出

**导出 CSV**：文件 → 导出数据 → 导出为CSV。所有字段（含收据 base64）写进 CSV。

**导出 Excel**：需要 `openpyxl`。写进 xlsx，列宽 15。

**没有导入功能**：目前只能导出，不能导入。想批量导入，可以先导出看格式，再自己写脚本插数据库。

工具 → 汇率转换：

## 第六部分：交易提醒自动填写——最实用的功能

### 6.1 为什么需要它？

你每天收到银行短信/微信提醒，格式大概是这样：

```
您尾号1234的储蓄卡9月18日14:30消费人民币12.34元，账户余额1,234.56元。
```

以前要手动抄：金额 12.34、商户（没有）、日期 2026-09-18 14:30、类型支出。现在**整段粘贴**，点一下，全自动填好。

### 6.2 支持的格式

**格式 A：微信/短信一行式**

```
您尾号1234的储蓄卡9月18日14:30消费人民币12.34元，账户余额1,234.56元。
```

**格式 B：银行 App 分行式**（标签 + 空格 + 值）

```
交易提醒
交易时间    2026年09月17日 22:58
交易类型    尾号3240的储蓄卡，存入
交易金额    人民币200.00
账户余额    人民币928.5
交易附言    存银行-DCEP010144081682
```

**格式 C：支付宝**

```
支付宝-肯德基（中关村店）
交易金额：88.00元
交易时间：2026-09-18 12:30
```

### 6.3 怎么用？

1. 点"添加记录"。
2. 在"标签"字段下方，找到"交易提醒信息"分组框。
3. 把提醒文本**粘贴**到文本框里。
4. **两种触发方式**：
   - 粘贴后等 350 毫秒，自动解析（防抖）。
   - 或者点"🔍 解析并填写"按钮。
5. 状态标签显示"✅ 已自动填写：类型=支出、金额=12.34、描述=肯德基、日期=2026-09-18 12:30"。
6. 检查一下，点确定。

### 6.4 识别规则详解

#### 金额识别（优先级从高到低）

1. **标签紧邻**：`交易金额：88.00` / `交易金额    人民币200.00`
2. **关键词附近**：`支出人民币12.34元` / `12.34元消费`
3. **带币种符号**：`¥88.00` / `￥88` / `RMB 88`
4. **带"元"**：`88元`
5. **其它小数**：`88.00`

**自动排除余额**：`账户余额1,234.56元` 里的 1234.56 **不会**被当交易金额，因为前面有"余额"。

**支持千分位**：`1,234.56` → 1234.56。

**支持万元/千元**：`1.5万元` → 15000。

#### 商户识别

**标签优先**：`交易商户：肯德基` / `商户名称    肯德基` / `收款方：张三` / `对方户名-李红玲`

**句式兜底**：
- `向肯德基付款` → 肯德基
- `支付给张三` → 张三
- `支付宝-肯德基（中关村店）` → 肯德基（中关村店）

**清洗规则**：按标点 `，,。；;、|` 截断、上限 30 字、去成对括号（但保留商户名内的括号）。

#### 交易附言（没有商户时用）

**标签**：交易附言 / 附言 / 交易摘要 / 摘要 / 交易备注 / 备注 / 交易说明 / 用途 / 说明 / 订单标题

**关键**（★ v4.7）：附言是**自由文本**，**不按逗号截断**，上限 100 字。

**举例**：
- `交易附言 银联无卡转账,对手户名-李红玲` → 完整保留"银联无卡转账,对手户名-李红玲"
- `交易附言 银联无卡转账,对手户名-李红玲 账户余额 人民币728.5` → 只取"银联无卡转账,对手户名-李红玲"（"账户余额"是下一个字段，切掉）

#### 日期时间识别

- 含年：`2026-09-18 14:30` / `2026年9月18日`
- 不含年：`9月18日` / `09-18`
- 相对：`今天` / `昨天` / `前天`
- 仅时间：用今天
- 时间格式：`14:30` / `14时30分` / `14点` / `下午3:05`

**跨年处理**：不含年且日期落在未来，按去年处理。

#### 收支方向识别

**强特征词**（优先）：
- 支出：支出、消费、付款、转出、扣款、取现、取款、支取、缴费、代扣、还款
- 收入：收入、入账、转入、存入、退款、冲正、工资、报销、利息、红包、汇入、到账、收益

**弱特征词**（无强特征词时）：
- 支出：支付、购买、扣费、汇出
- 收入：存款、退货

**特别注意**：弱词"支付"会跳过"支付宝/支付方式/支付成功"等品牌或状态词。所以"微信支付收款到账"会判成**收入**，不是支出。

## 第七部分：设置与持久化——为什么你的选择会被记住

### 7.1 设置存在哪？

每个用户的数据库 `finance_<用户名>.db` 里有一张 `settings` 表：

```sql
CREATE TABLE settings (
    key TEXT PRIMARY KEY,
    value TEXT
)
```

主库 `finance_master.db` 的 `settings` 表只存 `last_user`。

### 7.2 已持久化的键

| 键 | 含义 | 何时保存 |
| --- | --- | --- |
| `date_range` | 时间范围下拉框索引 | 变更时 |
| `last_type` | 最后选的类型 | 变更时 |
| `last_account` | 最后选的账户 | 变更时 |
| `last_category` | 最后选的类别 | 变更时 |
| `max_backups` | 最大备份数 | 变更时 |
| `backup_interval_hours` | 备份间隔小时 | 变更时 |
| `window_geometry` | 窗口几何（base64） | 拖动停止 800ms 后 |
| `window_maximized` | 是否最大化 | 同上 |
| `scroll_bottom_after_add` | 添加后是否滚到底（★ v4.9） | 点选即存 |

### 7.3 窗口几何实时保存（★ v4.4 / v4.5）

**三个入口**：
- `resizeEvent`：尺寸变
- `moveEvent`：位置变
- `changeEvent(WindowStateChange)`：最大化/还原

**流程**：
```
事件 → _schedule_geometry_save() → 800ms 防抖 → _save_window_geometry()
```

**不写的条件**：
- `_geom_restoring=True`（启动恢复期间）
- 窗口不可见
- 窗口最小化

**为什么要有防抖？** 拖动窗口时 `resizeEvent` 会触发几十次，每次都写库太慢。防抖 800ms 意味着你停手 800ms 后才写一次。

### 7.4 ★ v4.5 修复的 Bug（重要）

**现象**：窗口尺寸改了记不住。

**根因**：`load_settings()` 中间步骤 `update_date_range()` 末尾会调 `save_settings()`，而那时窗口还是默认尺寸 `resize(1200,800)`，默认尺寸被写进库。恢复几何的代码在函数最后才读库，读到的是刚写进去的默认值。

**修复**：
1. `load_settings()` **开头**先把 `window_geometry` / `window_maximized` 读到局部变量。
2. `save_settings()` 在 `_geom_restoring=True` 时**跳过**写这两个键。
3. `GEOMETRY_SAVE_DELAY_MS` / `_geom_restoring` / `_geom_save_timer` 默认值放**类级**，不用 `getattr(self, '不存在的属性', 默认)`——sip 对象上取不存在的属性会抛 `RuntimeError`。

**这三条在未来重构时必须保留。**

### 7.5 设置对话框（★ v4.9）

**打开方式**：工具 → 设置…

**特点**：
- 选项**点选即保存**，没有"保存"按钮，只有"关闭"。
- 复选框状态一变，立即回调 `_on_setting_changed(key, value)`，主窗口立即应用 + 写库。

**现有选项**：
- "添加记录后自动滚动到列表底部"（`scroll_bottom_after_add`）

**实现细节**：
- 对话框类 `SettingsDialog`，构造参数 `(parent, values, on_change)`。
- **先 `setChecked` 再连信号**，否则构造时会用默认值误触发一次"变化"。
- `load_settings` 里必须**先把新键读出来**（放在开头、`date_range` 之前），否则中间的 `update_date_range()` 会调 `save_settings()`，新键被类级默认值盖掉。

**新增选项的步骤**：
1. `_build_ui` 加控件 + `_bind_bool(控件, "键名")`。
2. `load_settings` 读、`save_settings` 写。
3. 类级默认值。
4. `_on_setting_changed` 里加分支应用。

### 7.6 维护要点（强制约定）

1. **文档 + 版本号同步**：每次改 `Finance_App.py`，必须同步更新本文档（迭代记录/功能清单/代码地图）并更新 `ProjectInfo.VERSION`。

## 第八部分：数据安全——备份、加密、撤销

### 8.1 备份

**手动备份**：文件 → 备份与恢复 → 手动备份。

**自动备份**：默认每小时一次。可设间隔（每小时/每天/每周/每月）和最大份数（默认 30）。

**备份文件命名**：`finance_<用户名>_<类型>_<YYYYMMDD>.db`
- 类型：auto / manual / before_restore

**清理**：超过 `max_backups` 份时，删最旧的。

**恢复**：
1. 文件 → 备份与恢复 → 恢复备份。
2. 弹出对话框，列出所有备份（时间、类型、大小、数据库版本）。
3. 可以按类型/日期筛选。
4. 勾选一个，点确定。
5. 恢复前会先自动备份当前数据（`before_restore`）。

### 8.2 加密

**加密**：
1. 文件 → 加密数据库。
2. 输入密码。
3. 程序用 PBKDF2（SHA256，100000 次迭代，固定 salt `b'some_salt'`）从密码派生密钥，再用 Fernet 加密整个数据库。
4. 密码存进主库 `users.password`。

**加密后**：
- 数据库文件变成密文，别人拿到也打不开。
- 程序运行时解密到内存（`:memory:`），操作内存库。
- 退出时把内存库导出、加密、写回文件。

**解密**：
1. 文件 → 解密数据库。
2. 输入密码。
3. 验证通过后，把明文写回文件，清空 `users.password`。

**注意**：加密用的是**固定 salt**，实际生产环境应该每用户唯一 salt。这是已知的安全简化。

### 8.3 撤销

**原理**：每次 `save_state_before_change()` 把当前数据库复制一份到 `temp_undo_*.db`，压栈（最多 10 个）。

**触发**：Ctrl+Z 或 编辑 → 撤销。

**限制**：
- 撤销栈在内存里，程序关闭就没了。
- 临时文件每 6 小时清理一次（超 24 小时的删）。
- 加密库的撤销文件也是加密的。

### 8.4 数据隔离

**多用户**：每个用户独立数据库 `finance_<用户名>.db`。切换用户时关闭当前库、打开新库。

**主库**：`finance_master.db` 只存用户列表和 `last_user`。

## 第十二部分：故障排查手册

### 12.1 程序打不开

**症状**：双击 exe 没反应，或闪一下就没了。

**排查**：
1. 看是不是把 exe 单独拎出来了——它需要同目录的 `icon.ico` 等文件。
2. 如果是源码运行，看命令行报什么错。
3. 检查 Python 版本是不是 3.10。
4. 检查依赖是否装齐。

### 12.2 窗口尺寸记不住

**排查**：
1. 确认版本 ≥ 4.5（4.4 有 Bug）。
2. 检查数据库 `settings` 表里有没有 `window_geometry` 键。
3. 如果是加密库，检查退出时是否正确写盘。

### 12.3 交易提醒解析不出来

**排查**：
1. 看提醒文本里有没有金额、日期。
2. 金额是不是被"余额"上下文排除了。
3. 试试手动点"🔍 解析并填写"。
4. 看状态标签提示什么。
5. 如果格式特殊，可能需要扩展识别规则（见 6.6）。

### 12.4 交易附言缺后面一段

**排查**：
1. 确认版本 ≥ 4.7。
2. 4.7 之前附言用商户清洗器，会在逗号处截断。
3. 升级到 4.7+ 即可。

### 12.5 筛选栏窗口太宽

**排查**：
1. 确认版本 ≥ 4.8。
2. 4.3 之前筛选栏最小宽度 1400+，4.3 降到 735，4.8 是 792。
3. 如果还是宽，可能是窗口几何存的是旧值，手动拖窄一次。

### 12.6 新增记录看不到

**排查**：
1. 确认版本 ≥ 4.6。
2. 4.6 之前时间范围锚定选择那一刻，程序开着过夜就会出问题。
3. 点"重置"或切到"全部时间"看看。

### 12.7 数据库打不开

**排查**：
1. 是不是加密库？需要密码。
2. 用 SQLite 工具打开，看文件头是不是 `SQLite format 3`。
3. 如果是密文，需要先解密。

### 12.8 编译后 exe 不是最新代码

**排查**：
Nuitka 在**编译开始时**读源码，编译要几分钟。如果编译启动后又改了源码，产物是旧的。

**验证方法**：
```powershell
Push-Location "项目目录"
& "D:/Program Files/Python310/python.exe" -c "import re;src=open('Finance_App.py',encoding='utf-8').read();v=re.search(r'\"(4\.\d+)\":\s*\"([^\"]+)\"\s*}',src);exe=open(r'build_output\Finance_App.dist\Finance_App.exe','rb').read();print(v.group(1),'在 exe 中:',exe.count(v.group(2).encode())>=1)"
Pop-Location
```
输出 `True` 才算最新。`False` 就重新编译。

| 定期交易 | 按周期自动重复的交易 |

## 附录 D：打包与编译

### D.1 Nuitka（主）

**脚本**：`0_nuitka_pyside6_clang_auto.bat`

**命令**：
```
--standalone --enable-plugin=pyqt5 --windows-console-mode=disable --jobs=4
--remove-output --output-dir=build_output --include-package-data=pypinyin
--include-data-files=icon.ico=icon.ico --windows-icon-from-ico=icon.ico
Finance_App.py
```

**输出**：`build_output\Finance_App.dist\Finance_App.exe`

### D.2 PyInstaller（备）

**脚本**：`9.bat`

**命令**：
```
pyinstaller --noconfirm --onefile --windowed --icon=icon.ico
--add-data "icon.ico;." Finance_App.py
```

### D.3 编码铁律

- bat 必须 **UTF-8 无 BOM + CRLF**。
- 首行加 `chcp 65001 >nul`。
- 验证：前 3 字节不应是 `239,187,191`。

### D.4 必须打包的数据文件

- `icon.ico`：主程序 `setWindowIcon(QIcon("icon.ico"))` 读的是 exe 旁的文件。
- `--windows-icon-from-ico` 只负责 exe 自身图标，不能替代 `--include-data-files`。

### D.5 不要打包的

- `finance_master.db`
- `finance_<用户>.db`
- `backups\`

见 12.8 节。
